**UPHOLD: A9** — verified, and my round-1 caveat on this lifts. `urllib.request.urlopen`: *"The optional timeout parameter specifies a timeout in seconds for blocking operations like the connection attempt."* Documented as covering blocking operations, not as an overall deadline for the transfer. The subprocess transports do have real deadlines, so the asymmetry I described is real.

**REJECT: D5** — verified. `subprocess.TimeoutExpired.stdout`: *"Alias for output, for symmetry with stderr."* The handler's `tail(e.stdout)` therefore does read the `output="".join(deltas)` the claude branch passes in, and the partial is not thrown away. Related, and worth recording as *not* a defect: the same docs say `output` *"is always bytes when any output was captured regardless of the text=True setting"*, so a `TimeoutExpired` raised by `subprocess.run(..., text=True)` in the codex/opencode branches carries bytes while the hand-raised one carries str — and `tail()` handles exactly that split (`b.decode("utf-8", "replace") if isinstance(b, bytes) else str(b)`). That branch is correct, not redundant.
